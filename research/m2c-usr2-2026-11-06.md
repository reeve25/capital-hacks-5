# M2c: USR 2.0 availability, 2026-11-06

**Measured availability; no inference or silent-accuracy result.** USR 2.0 remains
an open best-model option. Its fine-tuned Huge checkpoint is publicly reachable,
but the full file is 7.60 GB. A CPU resource/safe-loading probe is still needed;
file size alone does not establish that it cannot run on either laptop.

## Bounded availability check

For **3/3** files, Python `requests.get(..., stream=True, timeout=30)` against
`https://drive.usercontent.google.com/download`, with query parameters
`id=<above>`, `export=download`, `confirm=t` and header `Range: bytes=0-15`,
returned **206**, `application/octet-stream`, length **16**, the expected
`Content-Range` total above, and ZIP prefix
`504b0304000008080000000000000000`. Each response was closed after 16 bytes.
Google's public view metadata independently showed the Huge/Base+ sizes.
The availability probes read **48 bytes** of checkpoint body. Subsequent Huge
metadata probes read **1,048,576** and **400,002** bytes, for **1,448,626 bytes**
total across all probes. No full checkpoint, full-file hash, deserialization,
latency or RAM result was obtained.

The Huge ZIP starts with `model_avg_10/data.pkl` at data offset 64. Python
`pickletools.genops` parsed its opcode metadata through STOP at offset **399,937**
without executing pickle instructions or constructing tensors. It exposed
**2,352** `_orig_mod.` state-key strings: **1,169** `model.backbone` keys,
**1,169** `model.target_backbone` keys and **14** additional unlabelled-head/norm
keys. Storage GLOBAL records include `torch FloatStorage` and `torch LongStorage`.
This directly establishes separate backbone/target-backbone sets and FP32/integer
storage declarations, explaining why download size overstates the inference-only
backbone payload; exact tensor byte totals were not calculated. No optimizer
state was established. The inspected loader drops target-backbone/head entries.

## Loading, audio isolation and preprocessing requirements

Read [pinned demo.py](https://github.com/ahaliassos/usr2/blob/e9e9c94e8d827efbb28e9a4b9d5d2d97a583b129/demo.py)
before any run. Its loader explicitly uses `weights_only=False`; change the
ignored copy to `weights_only=True` with **no unsafe fallback**. Prefix removal
handles `_orig_mod.` and `model.backbone.`. The repository's evaluation entry
point has additional load calls requiring the same audit. No saving/training
code was found in `main.py` or `models/usr.py`; bounded file metadata above,
rather than a source saving function or size alone, establishes the second
backbone set. Its numerical relationship to the inference backbone is untested.

Default `modality=av` would allow dataset audio into recognition. Explicitly use
`modality=v`; the supplied demo still reads audio before selecting the visual
encoder branch, so a benchmark should strip/omit the audio stream independently
and assert visual-only encoder inputs. Disable `save_mouth_crop` or put its
retained output explicitly in ignored cache. Code resamples video to **25 fps**,
then aligns/crops, center-crops to **88x88**, converts to grayscale and normalizes
by mean **0.421**, std **0.165**. The
[detector](https://github.com/ahaliassos/usr2/blob/e9e9c94e8d827efbb28e9a4b9d5d2d97a583b129/preprocessing/landmarks_detector.py)
uses MediaPipe Tasks and needs a local `face_landmarker.task`; it is not the
older Chaplin `mediapipe.solutions` adapter. Capped CPU threads and batch one
remain required.
